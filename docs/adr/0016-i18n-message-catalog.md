# ADR-0016 다국어 메시지 카탈로그

- 상태: 승인 (사용자 결정 E-03, 2026-10-22)
- 일자: 2026-10-22
- 관련: PRD-I18N 계열, SRS 7.5절

## 맥락

- 사용자 결정: 영어와 한국어를 기본 제공, 언어 전환 가능 구조.
- 기계 판독 출력(JSON, 종료 코드, stdout 명령어)은 언어와 무관해야 함.

## 결정

- `Lang` 열거형(`En`, `Ko`)과 메시지 키 열거형 `Msg`, 언어별 `match` 함수로 카탈로그 구성. 와일드카드 분기 금지로 누락 메시지를 컴파일 오류로 검출.
- 자리 채움 메시지는 `{name}` 형식, 언어 간 자리 이름 일치 테스트.
- 언어 결정: `HOWTUI_LANG` > 설정 `ui.language` > `auto`(OS 로캘) > 영어.
- 외부 i18n crate(fluent, rust-i18n) 미사용.

## 근거

- 2개 언어, 수백 개 이하 메시지 규모에서 컴파일 타임 검증과 의존성 최소화가 런타임 카탈로그보다 유리.
- 언어 추가 시 `Lang` 항목과 match 함수 1개 추가로 확장.

## 대안

- (a) fluent: 복수형, 성별 처리 장점, 의존성과 런타임 파싱 비용으로 기각.
- (b) rust-i18n(YAML 카탈로그): 빌드 매크로 의존, 누락 검출이 런타임 기본값 대체로 약함, 기각.
